# 数据导入页面 CSV 上传交互框占位 Spec

## Why
当前项目已完成基础脚手架、数据库、登录认证与 Dashboard 骨架，但“数据导入”仍停留在导航占位状态，无法支持产品对后续导入流程的演示与评审。本次需要先补齐 PRD 中 `/settings/import` 数据导入页面里的 CSV 上传交互框占位，明确页面信息架构、交互反馈与视觉基调，为后续接入真实解析与 API 提交预留稳定边界。

## What Changes
- 新增 `/settings/import` 数据导入页面，并将侧边栏“数据导入”入口接入该路由。
- 按 PRD 的三步结构组织页面：下载模板、填写数据说明、CSV 上传交互框占位。
- 在页面主区域实现 CSV 上传交互框占位，包括拖拽区、点击选择文件入口、格式说明、上传状态提示与占位级 CTA。
- 仅处理前端本地交互反馈，不上传文件、不解析 CSV、不发起真实 API 请求。
- 延续当前项目的纯白极简杂志排版：白底、黑灰文字、细边框、大留白、克制强调色、信息优先。
- 为后续真实能力预留清晰边界，包括“CSV 模板下载占位”“待支持字段说明”“导入后校验区占位”“未来 API 接口替换点”。

## Impact
- Affected specs: Dashboard 导航、数据导入页面、CSV 上传占位交互、纯白极简视觉规范、无真实 API 请求边界
- Affected code: `src/components/protected-app-shell.tsx`、新增 `src/app/settings/import/page.tsx`、新增 `src/app/settings/import/layout.tsx` 或等效路由承载页、及可能拆分的局部展示组件

## ADDED Requirements
### Requirement: 数据导入页面入口可访问
系统 SHALL 允许已登录用户从 Dashboard 侧边栏进入数据导入页面。

#### Scenario: 从侧边栏进入数据导入
- **WHEN** 用户在后台侧边栏点击“数据导入”
- **THEN** 页面跳转至 `/settings/import`
- **THEN** 当前导航项显示为激活态
- **THEN** 页面标题与副标题清晰说明“上传 CSV 文件用于后续 GEO 数据导入”

### Requirement: 三步式导入信息架构
系统 SHALL 按 PRD 中定义的三步结构组织数据导入页面，以便用户理解后续真实导入流程。

#### Scenario: 查看页面结构
- **WHEN** 用户进入 `/settings/import`
- **THEN** 页面依次展示“第1步：下载模板”“第2步：填写数据”“第3步：上传文件”
- **THEN** 下载模板区域可先展示占位按钮或静态说明
- **THEN** 填写数据区域需列出核心字段或示例表头提示

### Requirement: CSV 上传交互框占位
系统 SHALL 在数据导入页面展示一个可交互但不执行真实上传的 CSV 上传框。

#### Scenario: 初始查看上传框
- **WHEN** 用户首次进入 `/settings/import`
- **THEN** 页面展示一个显著但克制的上传框区域
- **THEN** 上传框内包含标题、说明文案、支持格式提示与“选择 CSV 文件”操作入口
- **THEN** 页面明确提示当前为演示占位版本，尚未连接真实导入服务

#### Scenario: 选择本地文件
- **WHEN** 用户通过点击或拖拽方式提供一个本地文件
- **THEN** 页面仅在前端展示文件名、文件大小或类型等基础反馈
- **THEN** 页面不得发起网络请求
- **THEN** 页面展示“待接入真实解析流程”的占位提示

### Requirement: 文件格式限制反馈
系统 SHALL 对 CSV 以外的文件提供即时、明确且克制的前端反馈。

#### Scenario: 选择非 CSV 文件
- **WHEN** 用户选择非 `.csv` 文件
- **THEN** 页面提示仅支持 CSV 文件
- **THEN** 页面保留上传框结构，不进入真实上传流程
- **THEN** 错误反馈风格需与整体极简视觉保持一致，不得出现突兀弹窗

### Requirement: 占位级导入流程说明
系统 SHALL 通过静态说明区表达后续真实导入流程的预期步骤，但当前不执行任何真实业务逻辑。

#### Scenario: 查看导入说明
- **WHEN** 用户浏览数据导入页面
- **THEN** 页面展示 2-4 条导入说明，例如模板准备、字段校验、导入入库、结果回执
- **THEN** 每条说明仅作为信息架构占位，不显示伪造的成功结果或历史记录
- **THEN** 页面可额外展示 `date`、`visibility`、`citation_rate`、`sentiment_score`、`roi_index` 等样例表头作为静态参考

### Requirement: 纯白极简杂志排版
系统 SHALL 让数据导入页面与现有登录页、Dashboard 侧边栏保持统一的纯白极简杂志风格。

#### Scenario: 检查页面视觉风格
- **WHEN** 用户浏览数据导入页面
- **THEN** 主背景保持纯白或极浅灰白
- **THEN** 通过大标题、窄色域、细边框、分组留白建立阅读节奏
- **THEN** 避免复杂插画、厚重卡片阴影、渐变背景、装饰性动画与多余图标
- **THEN** 上传框应呈现“产品可演示、但仍是占位态”的克制质感

### Requirement: 无真实 API 请求
系统 SHALL 在本次实现中仅完成前端占位交互，不接入任何真实后端能力。

#### Scenario: 执行占位版本开发
- **WHEN** 用户在数据导入页面选择文件或点击相关操作
- **THEN** 页面不得调用真实上传接口、解析接口或入库接口
- **THEN** 页面不得伪造后端返回结果
- **THEN** 所有反馈均基于本地组件状态生成

## MODIFIED Requirements
### Requirement: Dashboard 导航完整性
此前 Dashboard 侧边栏中的“数据导入”仅为不可点击占位；本次起该入口应升级为可访问的实际页面入口。

#### Scenario: 查看侧边栏导航
- **WHEN** 用户进入后台
- **THEN** “数据导入”不再是灰态禁用文本
- **THEN** 而是可点击导航项，并在进入对应页面后保持激活态
