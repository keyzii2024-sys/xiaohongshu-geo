# 报告中心静态预览填充 Spec

## Why
当前项目已经具备登录、Dashboard 和竞品分析的静态演示能力，但“报告中心”仍未落地，导致“查看数据 -> 输出汇报材料”的核心演示链路不完整。优先补齐报告中心，可以最快形成符合 PRD 的可交付闭环，并验证纯白极简杂志排版在打印场景下的表现。

## What Changes
- 新增 `/reports` 受保护页面，展示“生成新报告”表单区和“历史报告”列表区。
- 新增静态报告预览页，用本地 mock 数据渲染符合 PRD 的杂志式报告内容。
- 提供“预览”和“导出 PDF”交互闭环，其中导出采用 `window.print()` 方案。
- 为报告预览页补充打印样式，确保纯白背景、隐藏交互元素、避免卡片和图表跨页切断。
- 将后台导航中的“报告中心”从占位态升级为可访问入口，并支持当前页激活态。
- 本阶段不接真实 API，不读取数据库，所有展示内容均来自本地静态 mock 数据。

## Impact
- Affected specs: 报告中心页面、报告预览页、打印导出样式、后台导航入口
- Affected code: `src/app/reports` 路由、后台共享布局导航、静态报告 mock 数据、全局打印样式或报告页局部样式

## ADDED Requirements
### Requirement: 报告中心入口页
系统 SHALL 提供可访问的 `/reports` 页面，作为报告中心的主入口。

#### Scenario: 进入报告中心
- **WHEN** 已登录用户点击后台导航中的“报告中心”
- **THEN** 系统进入 `/reports`
- **THEN** 页面展示“生成新报告”区域和“历史报告”区域
- **THEN** 当前导航项显示激活态

### Requirement: 静态报告生成表单
系统 SHALL 在 `/reports` 页面展示静态表单区，用于模拟报告生成流程，而不接真实数据源。

#### Scenario: 查看生成新报告区域
- **WHEN** 用户进入 `/reports`
- **THEN** 页面展示报告类型、时间范围与生成按钮
- **THEN** 表单文案与布局符合 PRD 的杂志式后台风格
- **THEN** 当前阶段所有默认值和展示结果均由本地静态 mock 数据驱动

### Requirement: 历史报告列表
系统 SHALL 展示静态历史报告列表，帮助用户理解报告中心的归档形态。

#### Scenario: 查看历史报告
- **WHEN** 用户滚动到历史报告区域
- **THEN** 页面展示至少 2 条静态历史报告
- **THEN** 每条记录至少包含报告名称、生成时间、类型和操作项
- **THEN** 操作项至少包含“预览”和“导出”

### Requirement: 杂志式报告预览页
系统 SHALL 提供静态报告预览页，按 PRD 的白底黑字杂志排版渲染完整报告内容。

#### Scenario: 查看报告预览
- **WHEN** 用户点击“生成报告”或历史报告中的“预览”
- **THEN** 系统进入报告预览页
- **THEN** 预览页展示封面、核心摘要、KPI、趋势分析、竞品对比、Top 问答与机会建议等主要版块
- **THEN** 文案、数值和模块顺序贴合 PRD 业务语境，不得出现无意义占位文本

### Requirement: 导出 PDF 交互
系统 SHALL 使用浏览器原生打印能力模拟 PDF 导出流程。

#### Scenario: 导出报告
- **WHEN** 用户在预览页点击“导出 PDF”
- **THEN** 系统调用 `window.print()`
- **THEN** 页面仅打印报告正文，不打印导航、操作按钮和其他交互元素

### Requirement: 打印样式控制
系统 SHALL 为报告预览页提供打印样式，确保导出结果稳定、整洁且符合 PRD 规范。

#### Scenario: 打开打印预览
- **WHEN** 用户触发打印
- **THEN** 报告页背景保持纯白，正文保持黑字
- **THEN** 导航、按钮和非报告元素被隐藏
- **THEN** 卡片、图表、表格和标题尽量避免被分页切断

### Requirement: 无真实 API 请求
系统 SHALL 在本次实现中完全基于本地静态数据渲染报告中心与预览页。

#### Scenario: 首次实现报告中心
- **WHEN** 开发本次需求
- **THEN** `/reports` 和报告预览页不发起真实 API 请求
- **THEN** 所有静态数据应集中管理，便于后续替换为真实接口或数据库数据

## MODIFIED Requirements
### Requirement: 后台导航能力
此前后台导航中的“报告中心”仅为不可点击占位；本次起其应升级为真实可访问入口，并接入现有受保护布局。

#### Scenario: 导航升级
- **WHEN** 用户查看后台侧边导航
- **THEN** “报告中心”显示为真实链接
- **THEN** 用户可从任意后台页进入 `/reports`

### Requirement: 受保护页面范围
此前受保护后台的重点页面集中在 `/dashboard` 与 `/competitors`；本次起 `/reports` 也应属于受保护页面范围。

#### Scenario: 未登录访问报告中心
- **WHEN** 未登录用户访问 `/reports` 或报告预览页
- **THEN** 系统重定向到 `/login`

## REMOVED Requirements
### Requirement: 报告中心继续保持占位
**Reason**: 占位态无法支撑产品演示闭环，也无法验证打印导出与杂志排版效果。
**Migration**: 使用静态 mock 数据先实现完整展示与打印流程，后续再替换为真实数据源。
