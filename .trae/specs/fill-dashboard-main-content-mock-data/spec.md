# 仪表盘主内容区假数据填充 Spec

## Why
当前项目已完成登录认证与 Dashboard 骨架，但主内容区仍为空白，无法验证 PRD 中“纯白极简杂志排版”的信息层级与演示效果。本次需要先以高保真假数据填充仪表盘主内容区，快速形成可评审、可演示的页面成品，同时明确边界为“不接真实 API”。

## What Changes
- 在 `/dashboard` 主内容区补全静态展示模块，包括问候语、KPI 指标卡、告警条、趋势图、Top 问答表格与机会分析师卡片。
- 使用结构化本地 mock 数据驱动页面渲染，确保文案、数值与趋势都贴合小红薯 GEO 业务语境。
- 落实 PRD 要求的纯白极简杂志排版：大留白、强标题、弱分隔、有限强调色、数据优先。
- 若仓库内尚未具备图表依赖，则补充轻量图表方案以支持“可见度趋势（我方 vs 竞品均值）”展示。
- 为后续接入 `/api/geo` 预留可替换的数据结构边界，但本次实现不得发起真实网络请求。

## Impact
- Affected specs: Dashboard 主内容区、杂志排版视觉规范、假数据边界、后续 API 替换策略
- Affected code: `src/app/dashboard/page.tsx` 及相关展示组件、静态 mock 数据模块、必要的图表依赖

## ADDED Requirements
### Requirement: 仪表盘主内容区假数据渲染
系统 SHALL 在已登录用户进入 `/dashboard` 时展示完整的主内容区，而非空白占位。

#### Scenario: 成功进入仪表盘
- **WHEN** 用户登录后访问 `/dashboard`
- **THEN** 页面展示问候语区、KPI 区、趋势区、问答区与机会分析区
- **THEN** 所有内容均由本地静态 mock 数据渲染

### Requirement: KPI 指标卡片
系统 SHALL 展示 4 个核心 KPI 卡片，且每张卡片需包含当前值、变化量与趋势方向。

#### Scenario: 查看核心 KPI
- **WHEN** 用户打开仪表盘
- **THEN** 页面展示 ROI 转化指数、情感健康度、可见度、引用率 4 张卡片
- **THEN** 每张卡片包含与 PRD 口径一致的业务名称
- **THEN** 数值表达需符合业务语义，如百分比、分值、pp 变化

### Requirement: 趋势图可视化
系统 SHALL 通过趋势图展示我方与竞品均值的阶段变化，并保持信息易读、样式克制。

#### Scenario: 查看趋势图
- **WHEN** 用户滚动至趋势区
- **THEN** 页面展示“可见度趋势（我方 vs 竞品均值）”图表
- **THEN** 图表至少包含日期维度、我方序列、竞品均值序列
- **THEN** 颜色使用黑灰基底与有限强调色，不得出现复杂渐变和花哨装饰

### Requirement: 告警与机会模块
系统 SHALL 在主内容区展示具备业务含义的风险提示与建议卡片。

#### Scenario: 查看风险与建议
- **WHEN** mock 数据中存在高危告警与优化建议
- **THEN** 页面展示一条高优先级告警条
- **THEN** 页面展示至少 2-3 条机会分析师卡片
- **THEN** 文案需贴合品牌运营与 GEO 策略场景，不得使用通用占位语

### Requirement: Top 问答表格
系统 SHALL 展示可读性清晰的高价值问答列表，用于模拟业务数据阅读场景。

#### Scenario: 查看问答排行
- **WHEN** 用户查看问答区
- **THEN** 页面展示 Top 5 问答排行表格
- **THEN** 每行至少包含问题、可见度、引用率、趋势
- **THEN** 表格在窄屏下仍不得造成横向滚动破坏整体布局

### Requirement: 纯白极简杂志排版
系统 SHALL 严格遵守 PRD 中的纯白极简杂志风格，确保信息表达优先于视觉装饰。

#### Scenario: 检查页面视觉风格
- **WHEN** 用户浏览 Dashboard 主内容区
- **THEN** 主背景保持纯白或极浅灰白
- **THEN** 以黑、灰、品牌红、正向绿作为有限色彩系统
- **THEN** 避免多余边框、复杂阴影、装饰图标、渐变背景与动画效果
- **THEN** 通过标题、字号、留白与分组节奏体现“杂志排版感”

### Requirement: 无真实 API 请求
系统 SHALL 在本次实现中完全基于本地静态数据渲染，不依赖 `/api/geo` 或任何外部请求。

#### Scenario: 首次实现假数据版本
- **WHEN** 开发本次需求
- **THEN** Dashboard 页面不发起真实网络请求获取主内容数据
- **THEN** mock 数据应集中管理，便于后续替换为真实接口返回

## MODIFIED Requirements
### Requirement: Dashboard 主内容区状态
此前 Dashboard 主内容区仅需提供极简空白占位；本次起该区域应升级为高保真假数据展示页面。

#### Scenario: 骨架升级
- **WHEN** 用户访问 `/dashboard`
- **THEN** 不再只看到标题与空白区
- **THEN** 而是看到完整的业务信息主内容
